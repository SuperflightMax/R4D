## TQA-02-01 — P2, consumer / Builder

**Реальное время может навсегда остановиться, хотя кнопка показывает «Пауза».**

Наблюдения на current02:

1. Seed4: при запуске из tick1000 два последовательных наблюдения сохранили
   tick1000 и кнопку «Пауза». В консоли — новый `RangeError` из `stepTicks`,
   вызванного кадровым callback `g` в текущем app.js.
2. Повтор на свежей загрузке без сетевой блокировки: начальный seed0 через
   «Продолжить» действительно дошёл до tick59. Затем через UI импортирован
   скачанный checkpoint seed `1842222754`, tick605. «Продолжить» и три
   pause/resume оставили tick605. Появился второй такой же RangeError с
   новым timestamp. Переключение кнопки цикл не восстановило.
3. В сломанном состоянии ручной «+1 тик» корректно дал tick606. Его state,
   PRNG и events точно совпали с oracle. Это не остановка native симуляции.

Краткий способ воспроизведения: свежая загрузка → дождаться 64 textures →
запустить run → импортировать обычный checkpoint605 → продолжить/поставить
паузу/продолжить. Ошибка зависит от времени попадания UI-события в кадровый
цикл; не утверждается, что каждое одиночное нажатие обязательно её вызывает.
После ошибки восстановление наблюдалось только через reload.

Ошибка: `RangeError: tick count must be a nonnegative safe integer`.
Stack в current app.js: `Object.x [as stepTicks]` 950:6280 →
`Object.stepTicks` 950:8024 → `g` 1000:31762.

Source reference на точном Builder commit:
`experiments/p4-extracted-objects/consumer/src/main.mjs`, start line25,
play toggle line28, frame lines54–60, вычисление delta/count lines56–57.
По коду вероятная причина: callback timestamp может оказаться меньше `last`,
заданного через `performance.now()` при UI start/resume; отрицательный delta
даёт отрицательное число шагов. Исключение выходит до планирования следующего
кадра. Локальное значение count в callback не инструментировалось, поэтому
это объясняющая гипотеза, а остановка и исключение — наблюдённые факты.

Ожидается устойчивое продолжение теми же native шагами после разрешённых
действий UI, без потери кадрового цикла. Ядро, config, PRNG, старт, геометрию
и траекторию для исправления менять не требуется.

Доказательства: `candidate-02/defect-realtime.json`; raw runtime
`realtime-stalled-t1000.jpg`, `realtime-stalled-t605.jpg`,
`realtime-manual606.jpg`, `realtime-fresh-errors.json`, `ui-records.json`.
Две RangeError записи отделены от намеренно вызванного ниже `Failed to fetch`.

  94→95→105→94. Terminal +1 не изменяет состояние.

  (LOST tick1058) и `228664868` (LOST tick1925). Оба сохранены без отбора.

  корректность их состояний при ручном продвижении до конца.
- Полные state/PRNG/events 59 наблюдений UI совпали с direct native oracle.
  Frozen native runtime и тот же exact source дали одинаковые 12 513
  состояний и накопленные events для семи действительно затронутых seed:
  двух новых random, двух сохранённых обычных Builder runs, seed1/4 из
  прежней подготовки и default0. Это проверка используемых runs, не новая
  поисковая матрица.
- Art/Geometry переключены независимо в четырёх сочетаниях. При Art-off
  контуры и проверочный шар видны без невидимого перекрытия. Геометрия
  показана поверх арта и строится из actual config; радиусы/сегменты
  соответствуют переданным входам.
- Из checkpoint605 сменены source/native view, camera-follow, zoom,
  Art/Geometry. Физическое состояние осталось605, следующий +1 снова дал
  ровно прежний606 с теми же PRNG/events.
- Изменённый config, повреждённый state и несовместимый binding отклонены

## Loading, пути и privacy

Проверены реальная загрузка и повторная загрузка root preview: 64 textures,
осмысленная сцена, исходно без console errors. Блокировка только
`input/config.json` в моей тестовой вкладке дала «Ошибка подключения» /
`Failed to fetch`; снятие блокировки и reload восстановили все64 textures.
Server/security не менялись. Tab-local блокировка снята, Network observation
отключено; собственная вкладка закрыта после проверки.

HTTP root/base-relative paths подтверждены на данном preview. Монтаж под
целевым Review prefix не проверен: такого работающего preview не выдано.
Page-level network capture не содержит внешнего HTTP-запроса; data/blob
декодеры присутствуют. Worker traffic отдельно не перехватывался, поэтому
полная сетевая изоляция этим capture не доказывается.

В фактическом root102 files: 100 payload + artifact/FROZEN. Нет TS/maps,
sourcesContent, sourceMappingURL или закрытого операторского пути в проверенных
текстовых bytes. Сканированы также метаданные. Private native source оставался
в ранее подготовленном собственном runtime. Public payload содержит только
исполняемый native bundle, соответствие которого проверено oracle.
