# P4: первый комплект для стыковки

`starter-v01/manifest.json`, версия `p4-starter-v01`.
Это небольшой комплект для реального стыка, ещё не полный арт и не QA PASS.

В комплекте flower-01, wood-01 и receiver-01. Сцена 1536×1536.
Фон восстановлен только под этими тремя объектами и их старыми тенями;
остальные 23 препятствия остаются в нём нарисованными. Полный config не менять.
На фоне после удаления корзины сохранены её подвесы; basket body и front
отдельно извлечены. Точность тонкой листвы/краёв нужно оценить в сборке.

## Контракт, предлагаемый Builder

- Пути PNG считаются от каталога manifest. SHA256 указан для каждого файла.
- `sourceRectPx`: `{x,y,width,height}` в исходном холсте.
  Без трансформации PNG располагается в `(x,y)` с единичным масштабом.
- `anchorSourcePx` — плоскость основания из P1, а не нижняя точка силуэта.
  `anchorLocalPx = anchorSourcePx - sourceRect.xy`. У всех частей объекта
  одинаковые sourceRect и anchor. Прозрачный padding размещение не меняет.
- `anchorNative` взят из exact config. `anchorResearch = anchorNative -
  [33256,34072]`. Прямая/обратная P1-матрицы даны в manifest. Смешивать две
  системы координат нельзя. Проверка обратного преобразования выполнена.
- PNG RGBA с straight alpha. Пусть PixiJS один раз выполнит premultiply при
  загрузке. Предварительно умножать RGB на alpha не нужно.
- `ground-shadow` один раз под телами и шариком; старые тени выбранных
  предметов удалены с подложки. Это восстановленная оценка alpha исходной
  тени, поэтому её заметность/кайму требуется проверить в обычном масштабе.
- `body` препятствия сортируется по `depth.sortNativeY` основания;
  сравнивать с native Y точки контакта шарика. Частичное перекрытие — alpha PNG.
- receiver `body` (задний обод и отверстие) перед шариком по порядку создания
  не подразумевается: рисовать его **до** шарика. `foreground` (передний обод
  и корзина) рисовать **после** шарика, пересекающего это отверстие.
  Пары не смещать и не дублировать. Это первый контракт для проверки,
  окончательное условие слоёв consumer требует реального стыка.

`restoration-regions.png` — область локально восстановленных пикселей фона,
не маска перекрытия в игре. За её пределами background RGB побайтно равен
декодированному исходному JPG. RGB извлечённых body/foreground также совпадает
с исходными пикселями; новых препятствий генератор не создавал.

`provenance.json` сохраняет контуры, происхождение и raw SHA;
`RUN_RECORD.md` — точные prompts и существенную ошибку первой ретуши.
`tools/prepare_starter.py` выполняет только подготовку/регистрацию этого
комплекта. Нужны Python, Pillow, NumPy, OpenCV и сохранённые raw в собственном
runtime. У скрипта нет доступа к private sim-core и нет логики движения.

Следующий шаг: Builder загружает эти точные PNG в PixiJS и подтверждает
координаты, alpha, тени, порядок частей и частичное перекрытие реальным шариком.
До получения результата стыка полная нарезка не начинается. Ball/shadow ещё
не входят в эту версию. Художественная пригодность только по файлам не заявлена.
