# Q1 — продолжение детального персонажа 6.1

Отдельное продолжение `experiments/gpt-6.1-sol/`. Дизайн сохранён; художник
исправляет привязки и локальные стыки. Исходный результат остаётся отдельно,
его неизменная production-копия включена в `public/baseline/` и показывается
через раскрываемое сравнение. У исходного baseline **нет низкой позы**.

## Запуск

Node 20.19+ или 22.12+. Проверено: Node24.15.0, npm11.12.1, PixiJS8.22.0,
Vite7.3.7. Из `D:\dev\R4D\experiments\q1-gpt61-continuation`:

```powershell
npm ci
npm test
npm run build
npm run preview
```

Открыть http://127.0.0.1:4181/. При занятом порте сервер сообщает ошибку.
Для ранней разработки: `npm run dev`. Production находится в `dist/` и
использует относительные пути; её можно раздавать из подпапки обычным
HTTP-сервером. Через `file://` не запускать. Публикацию в Review выполняет
назначенный Release Engineer; этот документ не задаёт адрес Review.

В production входят манифест, PNG из `parts/`, код и неизменный baseline.
Рабочие скрипты художника и временные браузерные журналы в сборку не входят.

## Смотреть и управлять

Кнопки работают мышью и обычным нажатием на сенсорном экране:

- **Покой /1** — живая стойка; **Низкая поза /2/S** — присед с реальным
  сгибом коленей/бедра и наклоном корпуса; **Идти /3** — цикл движения.
- **Прыжок /пробел** — из любого из этих трёх состояний. В воздухе можно
  выбрать новое наземное состояние; оно используется при приземлении.
- A/D или стрелки: удерживать для движения, отпустить для покоя.
- P — пауза; точка — шаг ровно1/60 секунды; B — кости; R — сброс.
- Светлый, средний и тёмный фон помогают видеть стыки и альфа-кромки.

Кнопки1/2/3 фиксируют выбранное состояние без удержания. Новая команда
доступна и в середине перехода; прыжок в воздухе повторно не запускается.
Пауза сохраняется при сбросе. Ручной ввод прерывает автопоказ.

В «Маршруты и замедление» доступны два маршрута из общих требований:

1. Покой → низкая поза → движение → покой → прыжок → покой.
2. Движение → низкая поза → прыжок → движение → прыжок → низкая поза.

Отдельные две кнопки меняют цель через0.06 секунды после запроса низкой
позы — на движение или на прыжок. Это смена в текущей промежуточной позе.
Маршруты подают обычные команды тому же механизму, их можно прервать.

## Механизм и привязки

Переиспользованы PixiJS-стенд и затухающая пружина первого прохода6.1.
Расширение Q1: выбранное наземное состояние хранится отдельно от фаз
прыжка. Все текущие параметры позы, положения таза и целей стоп проходят
через один механизм пружинного смешивания с сохранением скорости.
Отдельных клипов или таблицы переходов для пар состояний нет.

Затем одна и та же двухзвенная IK решает ноги по **уже смешанным**
положениям таза и стоп. Поэтому присед сгибает суставы и сохраняет опору;
масштаб всего персонажа одинаков для всех состояний. В полёте цели стоп
снимаются с земли тем же механизмом. Подготовка начинается с текущей
глубины таза, включая промежуточный присед.

`assets/manifest.json` хранит пиксельный pivot каждого PNG отдельно от его
crop, родительскую кость, смещение joint и слой. Физические длины/оси ног
вычисляются из joint; ненулевые X поддержаны. Draw order не выводится из
иерархии. Новая привязка плеч художника и локальная правка таза не требуют
перегенерации всего персонажа или смены runtime.

## Проверки

`npm test`: шесть проверок поведения — прыжки из всех наземных состояний с
каждым актуальным приземлением, опора в приседе, смена цели посередине,
оба маршрута, непрерывность угла околоπ, независимость суставных осей отcrop.
Это не автоматическая оценка художественной естественности.

Самопроверка браузерными вводами сохранена в `scripts/browser-smoke.js`.
Для её повторения нужен изолированный браузер Playwright CLI:

```powershell
npx --yes --package @playwright/cli playwright-cli -s=q1check open http://127.0.0.1:4181/
npx --yes --package @playwright/cli playwright-cli -s=q1check run-code --filename=scripts/browser-smoke.js
npx --yes --package @playwright/cli playwright-cli -s=q1check close
```

Она нажимает кнопки и клавиши, наблюдает фактические состояния, проверяет
обе обязательные последовательности и mid-transition-команды, шаг, мобильный
размер390×844 и загрузку iframe baseline. Для снимков создаёт
`output/playwright/`; этот каталог с временными материалами не входит вGit.
Если браузер Playwright ещё не установлен, CLI предложит его установить.

## Границы результата

Это заданные агентами координаты и процедурные позы одного героя, не
автоматический autorig. Кисти включены в предплечья, мягкая деформация
одежды не моделируется. Перекрытия и тёмные торцы оцениваются по собранным
позам; математическая непрерывность не гарантирует естественности.
Резкий разворот зеркалит персонажа сразу. На разгоне и в прыжковых
переходах возможно скольжение и задержка контакта стоп: решатель не является
физической симуляцией. Подробности подготовки арта и оставшихся визуальных
дефектов находятся в материалах художника/QA; решение о завершении — у CTO.
