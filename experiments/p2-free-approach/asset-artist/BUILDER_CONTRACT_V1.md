# Предложение Builder: шарик, тень и четыре пробы перекрытия

Путь пакета: `experiments/p2-free-approach/asset-artist/`.
Данные `asset-contract-v1.json` вычислены только из accepted P1 exact
`4b47db04c7140ebf88f69b91faa0b790d46f22ec`.

## Пространства и размеры

- Художественные точки и контуры заданы в исходных `1536 × 1536` source px.
- Позиция физики — native, без вычитания translation перед nativeToSource.
- Только `manifest.projection.nativeToSource` и её обратная матрица.
- Физический r = 16. Для source-размера `w = H20*x + H21*y + H22`,
  `s = 1/w`, `R = 16*s`. Оси самого шарика масштабируются одинаково.
- Центр картинки шарика — центр измеренного видимого диска, не центр canvas
  по предположению. После генерации будут сообщены реальный canvas и alpha bounds.
  Незаполненный `ball.assetPath` не разрешает автоматически брать шарик P1.

Контактная точка пола `A = H(nativeBallCenter)`. В этом первом художественном
предложении шарик — сфера на поверхности. Её видимый центр выше A:
`C.y = A.y - R*sqrt(1-k*k)`, где
`k = (d sourceY / d nativeY) / s` из локального Jacobian H.
Это оценка видимой высоты из принятой проекции, не изменение симуляции и
не точное восстановление камеры. Известные локальные `k` и `R` записаны в JSON.
Не растягивать круг в эллипс формы физического следа на полу.

## Тень

`shadow-native-disc-v1.png`: 128 × 128 RGBA, anchor `[64,64]`, рабочий радиус
48 texels. Диск описан в плоскости native. Масштабировать до native radius
`18.4` и спроецировать плоскую текстуру через H, как маленький floor quad/mesh.
Не проецировать сам шарик как плоскую наклейку.

Центр тени: native position + `[-8,+14]`. Это короткая тень вниз влево,
соответствующая наблюдаемому свету сверху справа. Максимальная alpha в PNG
0.30; первое применение — normal blend, tint белый, дополнительная opacity 1.
Так сохраняется её собственный тёмный зелёно-коричневый цвет.
Суммарная плотность/смещение проверяются в обычном масштабе. Это стартовая
настройка, а не доказанное художественное соответствие.

Существующие тени препятствий уже остаются внутри JPG; не рисовать их повторно.
Тень шарика ограничить полом и вычесть силуэты стоящих объектов: тёмный овал
не должен закрашивать их бок/верх. При попадании на уже тёмный участок пола
сохраняется одна тень шарика; не добавлять второй контактный овал автоматически.

## Перекрытия: малый пример

К стыку Lead/Builder принят `occluders-v1.json`:

```text
occluders[] = {id, file, sourceRect:[x,y,w,h], depthNativeY,
               baseAnchorSourcePx, polygonSourcePx, polygonRectLocalPx}
```

`file` — неизменённый `01-jungle.jpg` с проверенным SHA; Builder использует свой
уже подключённый локальный путь. `sourceRect` задаёт абсолютную регистрацию,
`polygonRectLocalPx` — ограничение исходной текстуры внутри прямоугольника.
Можно рисовать полигон с UV исходного JPG или растрировать его в runtime.
Нельзя растянуть прямоугольник к размеру pin или включить в контур его тень.
`depthNativeY` точно равен pin.y. Это простой первый прототип: при переключении
глубины возможен заметный скачок, который проверяется на боковом контакте.
Несколько частей одного объекта допустимы после наблюдения причины.

`occlusion-probes-v1.json` сохраняет исходную ручную разметку. Физические центр/r
берутся из фактического accepted config, с проверкой совпадения ID. Полигон
обозначает видимую опору вместе с верхом, без падающей тени. Сам полигон
не collider. Погрешность контура — предмет визуальной коррекции, не повод
изменять config.

При наблюдаемом скачке для следующего попиксельного сравнения можно принять опору за вертикальную
экструзию круглого collider. В локальной камере около опоры, с масштабом `s`,
наклоном `k` и `c=sqrt(1-k*k)`, рассмотреть пиксель шарика:

1. `u=(sourcePixel.x-ballScreenCenter.x)/ballScale`,
   `v=(sourcePixel.y-ballScreenCenter.y)/ballScale`.
2. Для `u²+v² <= rBall²` ближняя поверхность сферы имеет native-глубину
   `yBallSurface = ball.y + k*v + c*sqrt(rBall²-u²-v²)`.
3. Native X пикселя возле опоры: `xColumn = pin.x +
   (sourcePixel.x-project(pin).x)/pinScale`.
4. Передняя поверхность опоры: `yObject = pin.y +
   sqrt(max(0,pin.r²-(xColumn-pin.x)²))`.
5. Только внутри художественного силуэта закрывать пиксель шарика, если
   `yObject > yBallSurface`. Для свеса за пределами радиуса стартовая оценка
   `yObject=pin.y`; она особенно нуждается в проверке боковых проходов.

Это простой визуальный proxy, а не новая 3D-физика. Он имеет ограничения:
реальные лепестки/лягушка не вертикальные цилиндры; локальная камера —
приближение проективного H. Силуэт + этот тест должны быть проверены в движении.
Если proxy даёт разрыв, корректировать художественную глубину/контур или
сменить способ отображения; не двигать принятую опору.

Шарик, его тень и ограничения их видимости принадлежат переключателю «Арт».
Проверочная геометрия и диагностический путь находятся выше и вне этих масок.
Смена масштаба сцены применяется после всех source-координат одинаково.
