# Стык P2 с Artist

Первый пример — по одному цветку, листу, лягушке и столбику. Остальные препятствия пока остаются только в неизменном фоне: это ограничение примера, не завершённая система перекрытий.

Фон — точный `01-jungle.jpg` размером 1536×1536. Свет и тени исходника сохраняются. Прозрачные накладки содержат только видимую поверхность объекта, без прямоугольного фона и падающей тени. Накладка возвращается поверх шара для прохождения за объектом. Её пиксели совпадают с фоном по позиции и цвету. Геометрия не меняется.

Manifest `r4d.p2.assets.v1`:

```json
{
  "schema": "r4d.p2.assets.v1",
  "sourceSize": [1536,1536],
  "mode": "art",
  "ball": {
    "file": "ball.png",
    "centerPx": [256,256],
    "diameterPx": 400,
    "liftRadii": 0.8
  },
  "shadow": {
    "file": "shadow.png",
    "centerPx": [256,128],
    "footprintPx": [400,200],
    "nativeRadii": [1.15,0.65],
    "offsetNative": [8,12],
    "opacity": 1
  },
  "occluders": [
    {
      "id": "leaf-01",
      "file": "leaf-01.png",
      "sourceRect": [700,320,150,110],
      "depthNativeY": 33328.97811206313
    }
  ]
}
```

Числа размеров/кропа выше — пример контракта, не утверждённая разметка. `file` — путь относительно manifest. `sourceRect` определяет место и размер накладки в пикселях исходника. В `id` используется ID принятого pin/bucket; части одного объекта могут иметь один ID. `depthNativeY` — только порядок отображения, не новый коллайдер. Если поле отсутствует, берётся `config.board.pins[id].y` или `buckets[id].y`. Явно назначенный depth объясняется наблюдением, а не подгонкой физики.

В принятом малом пакете Artist `fc892908d54cd06a44eb785edea4a9c5b32e3c97` отдельные вырезанные PNG не требуются: `fileRole:"source"` берёт текстуру из неизменного JPG, `sourceRect` задаёт её точный кроп, `polygonRectLocalPx` ограничивает его видимым силуэтом. Абсолютный контур и anchor сохраняются в manifest для QA. Adapter `scripts/prepare-artist-probe.mjs` читает только этот exact commit, проверяет четыре ID/native-y и SHA256 тени, пишет небольшой manifest+тень в runtime Builder. Исходник не редактируется.

Прозрачный край или source-полигон накладки обеспечивает частичное перекрытие. Простая смена порядка по native-y — проверяемая гипотеза первого примера. Само наличие накладок не доказывает отсутствие скачка: смотрим боковой отскок, кадры до/во время/после перехода и широкую верхушку. При видимом скачке сначала проверяем точность силуэта и его соответствие принятому основанию, затем обоснованно делим конкретный объект на части.

Для корзины накладка переднего борта отдельная: не закрывать всё тёмное отверстие. Порог задаётся видимым передним бортом и проверяется на настоящем входе.

Ball: центр и диаметр относятся к самому кругу внутри PNG, без прозрачных полей. Изображение сохраняет сферическую форму; диаметр следует локальному горизонтальному масштабу неизменной проекции. Если `liftRadii` не задан, подъём вычисляется из локального Jacobian по предложению Artist: `R*sqrt(max(0,1-k*k))`, где `k=(d sourceY/d nativeY)/s`. Это художественная оценка камеры, не новая физика. Явный `liftRadii` может задать согласованную Artist коррекцию.

Shadow: отдельный PNG. Центр и `footprintPx` относятся к содержимому. `nativeRadii` — полуоси относительно физического радиуса 16, `offsetNative` — смещение на native-плоскости. Для тени применяется локальный якобиан принятой проекции. В малом пакете Artist — диск native radius18.4 и смещение [-8,+14], alpha уже внутри PNG. Все четыре силуэта вычитаются из тени независимо от глубины шара: плоская тень не закрашивает верх/бок видимого объекта. Этот проход лежит ниже шара и не скрывает его. Параметры не расходуют PRNG.

Диагностика — всегда последний слой выше накладок. При выключенном арте видны чистая фактическая геометрия, проекция диагностического круга и путь. При выключенной геометрии диагностическая разметка не заменяет финальный шар. До собственного сгенерированного растрового шара/тени режим называется `diagnostic`, художественный PASS невозможен.

Запуск с готовым manifest: `node scripts/serve.mjs --assets E:/R4D/perspective/p2-runtime/пакет/manifest.json`. Artist готовит файлы в своей области; Builder не меняет его worktree.
