## До первого solve — точный R2_SOLVER_CONTRACT

Builder готовит `R2_SOLVER_CONTRACT.md`, окончательный solver code и input/code hash manifest. Сначала явно фиксируются objective/barrier/schedule, tolerances, maximum iterations/substeps, deterministic seed, stall/fail criteria и разумные distortion/conditioning thresholds с обоснованием. Договор читает Lead, Concept/Asset сверяют смысл недопустимого collapse/stretch. После сохранённого/опубликованного договора Lead даёт отдельный старт единственного actual-input solve. До этого допустима проверка реализации/аналитических производных на синтетических данных, но не подбор параметров по actual targets/witness.

**Единственное изменение:** harmonic initial iterate заменяется orientation-preserving nonlinear continuation, seeded последним принятым positive state. Между двумя неизменными output targets допустимы детерминированные adaptive homotopy substeps граничных pins. Каждый substep — тот же ARAP + finite log-det/orientation barrier либо математически эквивалентная явно constrained positive-det оптимизация с trust-region/line-search. На принятом endpoint pins exact в заранее объявленном tolerance. Подшаги — только численный путь, не новые output targets и не покадровая ручная коррекция. Seed/получение первого low0 также описать явно.

После результата **не тюнинговать** закон/параметры по witness. Исправление доказанного implementation bug допускается только с отдельным audit **и прямым решением CTO**; Lead сам не разрешает такой повтор. При FAIL/stall/collapse/excessive distortion R2 закрывается как последняя численная отрицательная проверка, без третьего solver/другой topology/anchors.
