# Промежуточный вход garment04: сверка Builder

Материал Asset прочитан; PNG не менялись. Тело02: все 11 PNG, crop и bindings совпали с immutable02 (`MATERIAL.json`).

1. **Metadata anchor:** в прочитанном `PANELS.json` и live `parts.json` у farFlap C ещё `(638,754)` вместо утверждённого **`(634,758)`**. В коде Builder с самого начала закреплён только утверждённый `(634,758)`; другой anchor не испытывался. Для промежуточного визуального просмотра применяются именно договорные константы, расхождение данных раскрыто. Перед согласованным stable after Asset должен привести metadata к общему договору. Art сам не правлю.
2. **Exact source-neutral RGBA:** собственная read-only проверка подтвердила данные Asset. Visible-only композиция совпадает с reference побайтно; обычный source-over фактических панелей с hidden copies отличается у **3015** пикселей, максимум alpha **5**, RGB самих RGBA без изменения. Первый пример `(505,592)`: `[24,13,16,253] → [24,13,16,255]`. `NEUTRAL_RGBA.json` сохраняет независимые числа. Это не exact RGBA PASS; coverage 0/0 не подменяет проверку состава слоёв. Специального compositor, нормализации alpha или удаления запаса ради равенства не добавляю.

По разрешению Lead продолжается только промежуточный реальный просмотр верхнего шва/подола/объёма с договорными anchors, пока Asset завершает выдачу. Не замораживать эти расхождения как согласованный PASS. Body coverage/B/repair закрыты.

Source-neutral без запасов точен, с реальными запасами не является exact RGBA PASS. Stable after сохраняется как отрицательная garment-попытка, не согласованный PASS.
