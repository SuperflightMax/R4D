# Запуск и границы текущей сборки

Из `D:\dev\R4D\experiments\q4a-whole-character`:

```powershell
npm ci --no-audit --no-fund
npm run dev
```

Адрес: `http://127.0.0.1:4194/`; другой порт задаётся через `Q4A_PORT`. Сервер только loopback. JS/CSS компилируются при запуске; после изменения кода выполнить `npm run build` и обновить страницу. Сервер читает текущий `art/` напрямую, кнопка «Перечитать арт» загружает появившийся `parts.json`. Для отдельного статического пакета `npm run build` копирует арт в `build/site/art/`.

`npm run check` проверяет общий механизм на синтетических ориентирах: прерывание перехода, последнюю цель в полёте, отсутствие двойного прыжка, конечность координат, постоянство длин сегментов и шаг времени. Эти тесты не доказывают художественную пригодность Мирона.

Файлы новой реализации: `app/motion.mjs`, `app/main.mjs`, `app/index.html`, `app/style.css`, `build/build.mjs`, `build/serve.mjs`. Контракт частей — `builder/PARTS_CONTRACT.md`; точную структуру адаптируем по фактической разметке Asset. Старые runtime, риг, арт и движения не читались и не копировались.

Пока частей нет, показан неподвижный цельный v01 с прямой подписью и недоступными командами анимации. Это служебный просмотр исходника, не анимационная попытка и не выбор v01 вместо ожидаемого утверждённого источника. Во встроенном браузере проверены загрузка Pixi/WebGL, правильная прозрачность цельного v01 на тёмном фоне, переключение фона и паузы. Реальные движения UI, плечо/таз и пригодность v02 ещё не проверены.

При загруженных частях: команды 1/2/3/4 — idle/low/walk/jump; наземная цель в полёте применяется после посадки. Pause не накапливает прошедшее реальное время. Step ставит на паузу и продвигает ровно 1/60 секунды симуляции независимо от выбранного замедления. Slowdown 1/0.5/0.25/0.1; пауза и команды доступны одновременно. «Суставы» показывает ориентиры поверх реального арта. `window.q4a.snapshot()` — чтение диагностического состояния, не альтернативный механизм управления.

Первая значимая анимационная сборка с реальными частями ещё не получена. Её сохранение и ранний художественный просмотр — следующие обязательные действия после подготовки разрешённых материалов. Stage/commit/push выполняет Lead.

## Ограниченный gate v02

По следующему решению CTO текущий интерфейс жёстко ограничен neutral/low; walk/jump отклоняются также самим механизмом, включая клавиатуру. После появления измеренных `contacts` и минимальных частей из v02 кнопка «Исходная раскладка» показывает before без поворотов, «Покой» — neutral с общей линией опоры, «Присед» — глубокий low. Выравнивание использует повороты реальных стоп и одно общее смещение таза при неизменных длинах; при недостижимости контактов численный отчёт показывает ошибку, а не растягивает ногу. Геометрические тесты не подтверждают объём реального тела.

Для сохранения фактических длин/углов/контактов после получения `art/parts.json`: `node builder/measure-early.mjs`. Затем `npm run build` и `node builder/save-early.mjs` сохраняют первую значимую сборку в `build/early-v02-01/`; повторная запись туда запрещена самим скриптом. До реальных частей эти команды сохранения не выполнялись. Численные результаты будут в `builder/early-v02-01/measurements.json`. После перезапуска dev-сервера сохранённый просмотр доступен по `/early-v02-01/`.

Сейчас подготовка расчёта и ограниченного интерфейса закончена; фактические части, их правильные маски и вывод об опоре/плече/тазе остаются зависимостью Asset и следующего просмотра. Это не PASS gate и не полный кандидат.

Актуализация после получения частей: первая реальная попытка сохранена в `build/early-v02-01/`, данные/кадры и отрицательный вывод Builder — в `builder/early-v02-01/RESULT.md`. Стабильный просмотр для Concept: `http://127.0.0.1:4194/early-v02-01/index.html`. Предыдущие записи об отсутствии частей описывают подготовительный этап. Части/маски снимка побайтно совпали с комплектом после окончания самопроверки Asset; полной подготовки и приёмки пока нет.
