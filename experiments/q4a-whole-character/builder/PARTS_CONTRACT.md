# Контракт загрузки Q4A

Для Asset Artist и Lead. Договорный смысл координат сохраняется. Предлагаемый минимальный JSON для новой сборки:

```json
{
  "source": "source/whole-v01.png",
  "sourceSize": [1024, 1536],
  "figureBounds": [200, 100, 600, 1300],
  "jointPoints": {
    "pelvis": [500, 760], "chest": [500, 480], "neck": [500, 350], "head": [500, 250],
    "nearHip": [510, 780], "nearKnee": [540, 1050], "nearAnkle": [520, 1310], "nearToe": [600, 1340],
    "farHip": [480, 780], "farKnee": [450, 1050], "farAnkle": [430, 1310], "farToe": [500, 1340],
    "nearShoulder": [520, 420], "nearElbow": [550, 620], "nearWrist": [570, 800], "nearHand": [590, 850],
    "farShoulder": [480, 420], "farElbow": [440, 620], "farWrist": [420, 800], "farHand": [430, 850]
  },
  "parts": [{ "id": "nearUpperArm", "file": "parts/near-upper-arm.png", "cropRect": [470, 380, 120, 290],
    "from": "nearShoulder", "to": "nearElbow", "z": 40 }]
}
```

Числа здесь только пример формата, не схема тела Мирона и не готовый риг. `figureBounds` — прямоугольник непрозрачной фигуры `[x,y,width,height]`. Все точки — на исходном холсте; cropRect задаёт положение обрезки, расширенное при достройке. `file` и `source` относительны `art/parts.json`. Ширина/высота PNG совпадают с cropRect; никакого скрытого растяжения.

Для torso подходят from pelvis → to neck; для pelvis — pelvis → chest (ориентация таза отдельно будет уточнена по реальному арту); head — neck → head; кисть — wrist → Hand; стопа — ankle → Toe. Слой `z` задаёт Asset по исходному изображению. Необходимость отдельных передних/задних фрагментов решаем после раннего просмотра.

Если у уже готовой разметки другие имена/структура, Builder адаптирует загрузчик один раз после чтения фактического JSON; не требуется переделывать изображение под этот пример. Полезнее точные анатомические точки и происхождение, чем формальное совпадение названий.

До готового parts.json интерфейс явно показывает отсутствие анимационных частей, без технического героя вместо арта. Источник при наличии показывается отдельно как неподвижный исходник. Кнопка «Перечитать арт» обновляет материалы после сборки сайта.

## Ограниченный тест v02 по решению CTO

Нужны фактические суставы обеих цепей ног и выбранные контакты подошв (желательно пятка и передняя опора, не носок в воздухе). Дополнение к данным: `mode: "early-neutral-low"`, `contacts: { near: { heel: [x,y], toe: [x,y] }, far: { heel: [x,y], toe: [x,y] } }`. Общий `groundY` можно задать явно либо принять как максимальную высоту нижнего контакта в исходнике. Наклон стопы определяется этой парой опор, без масштабирования. Точные имена и вложенность Builder адаптирует к фактической разметке; не жду полного комплекта кистей/головы, если они включены в торс/предплечье.

В раннем интерфейсе будут исходная раскладка в координатах v02 (before), neutral с общей опорой и глубокий low (after); walk/jump отключены до разрешения полной подготовки. Длины и углы обеих ног, координаты heel/toe и изменение root сохраняются численно. Для плеча нужны реальные части торса и ближней руки с pivot; отсутствующие поверхности не будут заменены техническими фигурами. Необходимый минимум частей определяет Asset по принадлежности пикселей, а не этот пример JSON.
