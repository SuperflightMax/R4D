## Оформление J и геометрия

См. [контактный лист колена](output/playwright/knee-contact.png), отдельные `J-*.png`, светлый/тёмный .42/.84 в `output/playwright/`. Лист — фиксированные кропы реальных браузерных screenshots с увеличением для чтения, не новый рендер и не исправление арта.

- **J0:** замкнутый тёмный торец и отделяющая поперечная граница отчётливо видны в bind, крайних и промежуточных положениях. Правильная привязка сама их не устраняет.
- **J1/M2:** вместо среза видна ткань; на наблюдённых кадрах колено выглядит менее разрезанным. Это частичный результат. Запас бедра сократился, остались жёсткая форма сгиба и тёмные складки/границы. Изменился не только контур, поэтому этот проход не доказывает причинный эффект одного удаления внутренней линии.
- **J2:** точная подложка J1 и узкая наклонная накладка. Она восстанавливает часть силуэтного покрытия, но даёт выступающий угловатый край/дополнительную границу, особенно при 92° и jump phase. Метрическая прибавка покрытия не означает художественной победы.

Независимый расчёт [geometry-results.json](geometry-results.json) использует actual browser transforms и native RGBA: сетка 0.5 canonical px в квадрате ±64 вокруг оси; площадь перекрытия — внутри диска радиуса 28, alpha≥128. Проверены **78 состояний каждого из пяти вариантов**, всего 390 расчётов, в том числе все пять конечных поз и движение между ними. Это модель покрытия текстур, не чтение framebuffer WebGL.

|---|---:|---:|---:|
| J0 | 1389.25 | 0 | 0 |
| J1 = M2 | 629.00 | 0 | 571.50 |
| J2 | 629.00 | 0 | 25.75 |
| M1 | 1247.00 | 0 | 0 |

Минимальное перекрытие J1 соответствует примерно **110.96 intrinsic px² при .42** либо **443.82 при .84**, до CSS; максимальная потеря покрытия — примерно 100.81/403.25 px². Это эквивалент площади по масштабу, а не число фактически окрашенных экранных пикселей. Крупного разрыва/отрыва на просмотренных кадрах не найдено. У J1/M2 на одном intermediate sample найден единственный enclosed alpha-threshold участок **0.25 canonical px²** (0.0441 intrinsic px² при .42); это ниже точности визуального вывода о дыре и не блокер. J2 его перекрывает.

Подсчитана также тёмная площадь при luma<30; она не является детектором внутренней линии. Например, при 92° J0 даёт 123.25 canonical px², J1 439.75, M1 896: тёмные складки/полость влияют на число сильнее видимого среза. Поэтому вывод о торце основан на кадрах и источниках пикселей, а не на ложном правиле «меньше тёмного = лучше». Отсутствие gap не доказывает естественную форму, запас при всех возможных углах или физическую корректность.

Это подтверждение предоставленной provenance; QA не наблюдал сами вызовы и не может доказать отсутствие незаписанных вызовов. Mask API в args отсутствует, маска передавалась reference; нулевой final diff не приписывается генератору. Универсальное превосходство M2 и повторяемость из одного случая не следуют.

## Ограничения и решение

Технических дефектов, мешающих сопоставить результаты, не найдено. Остаточные недостатки содержательны: J0/M1 торцы, укорочение/потеря запаса J1/M2, выступающая накладка J2, обрезание дистальной части на фиксированном zoom. Они сохраняются в результате, а не снимаются статусом QA. Проверка измеряет локальное соединение; полного персонажа, контакта с землёй, физики прыжка, человеческого восприятия, всех времён requests/браузеров и 60fps она не доказывает.

**Stop/show оправдан:** замороженный стенд даёт раздельный ответ по привязке, оформлению и получению; обнаруженные потери являются результатом разрешённых однократных маршрутов. Новая генерация/подгонка без новой гипотезы превратит этот проход в доводку. Если CTO захочет отдельную коррекцию, она должна явно назвать оставшийся вопрос; технической необходимости блокировать показ сейчас нет.

Инфраструктурные ограничения раскрыты: первый запуск QA CLI не открыл страницу из-за отсутствующего ожидаемого chromium_headless_shell-1247. Использован уже установленный изолированный Chromium-1208 через executablePath; ничего не устанавливалось, личный Chrome не использовался. Отдельная CLI попытка Builder с SyntaxError произошла до действий страницы по его записи; основной self-check завершён. Ни то, ни другое не считается дефектом Q6. Важные свойства проверены здесь независимо. Первичный текстовый экспорт QA искажал кириллицу из-за кодировки shell; исправлен только способ выгрузки через UTF-8/base64, браузерный pass не повторялся. Канонический [browser-results.json](browser-results.json) содержит правильный Unicode.
