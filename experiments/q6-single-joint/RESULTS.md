# Q6 — результат одного полного прохода

23 октября 2026. **CTO принял `q6-c1`: stop/show with limitations, без correction.** [Решение и основание](CTO_DECISION.md). Исследовательский ответ получен; качественный производственный сустав и универсальный рецепт не получены. Весь продукт остаётся в исходном frozen-виде, неудачные варианты сохранены.

Локальное демо: http://127.0.0.1:4186/ , переданный Vite PID `63020`. [CANDIDATE.md](CANDIDATE.md) описывает запуск (`npm ci`, `npm run dev`), управление и ограничения самопроверки. Публичный релиз ожидается отдельно; будущий route `/review/r4d/q6-single-joint/` ещё не опубликован этой работой.

## 1. Диагностика сборки, отдельно от рисунка

Взят исходный Sky Courier 5.6: две ближние части ноги, master, manifest, rig и animation. Все шесть exact source SHA проверены и копии сохранены в `provenance/source/`; originals не менялись. [BRIEF.md](BRIEF.md) и [контракт](FROZEN_CONTRACT.json) содержат первоначальную диагностику.

Declared knee `[139,319]` минус thigh pivot `[98,35]` даёт `[41,284]`, длина ≈286.944 согласуется с declared 287. Runtime игнорировал `childJointPx` и задавал `[39,240]`: точка `[137,275]` вместо объявленной `[139,319]`. В bind при renderer scale .42 source shin на `[-.84,-18.48]` экранного px относительно neutral. QA проверил также повёрнутую разность. Это доказанное рассогласование с объявленной геометрией, а не предположение о качестве арта.

Neutral comparison для **всех** J/M использует `[41,284]`, прежние pivots `[98,35]`/`[102,28]`, layers `-10/-11`, fixed camera/scale. Runtime override shin `-11` соответствует текстовому правилу cap behind thigh, хотя numeric manifest содержит `-9`; новый опыт со слоями не проводился. Семантическая ось сохранена, её физическая идеальность по одному PNG не установлена.

Source-vs-neutral diagnostic использует одинаковый J0: положение/перекрытие меняются, но тёмный торец остаётся. Поэтому исправление привязки не считается ремонтом рисунка. Это отдельный результат, не четвёртый J-вариант.

## 2. J-design: что дало оформление на одном риге

| Вариант | Результат в сборке |
|---|---|
| J0 — точные original PNG | Тёмный замкнутый торец отделяет бедро от голени уже при .42; отрицательный контроль сохранён. |
| J1 — именно M2 final | Ткань вместо ложной плоскости делает стык цельнее. Остались жёсткий бугор, сужение/ступенька и несогласованный шов; запас бедра уменьшился. |
| J2 — точная J1 подложка плюс отдельный мотив | Геометрическое покрытие выросло, но узкая наклонная деталь выступает углом и читается лоскутом. Убедительный наколенник не получился. |

Автор и оба независимых QA согласны с частичным преимуществом J1 по видимой непрерывности. Это результат реально изготовленной связки: одновременно изменились линия, складки, форма и запас. Изолированный причинный эффект удаления одного контура не доказан; непригодность любых накладок тоже не следует из неудачи этого J2.

Technical QA оценил native alpha на actual browser transforms в 78 состояниях каждого варианта: min overlap J1/M2 629 canonical px² против 1389.25 у J0; max gap между сегментами 0 на выборке. Max loss покрытия относительно J0 в диске: J1 571.50, J2 25.75 canonical px². Единичный enclosed alpha-threshold участок J1 — 0.25 canonical px², ниже основания объявлять видимую крупную дыру. Это дискретная модель покрытия и отдельная метрика, не оценка красоты или гарантия всех углов. На просмотренных кадрах крупного разрыва не обнаружено.

## 3. M-method: получение строго целевого J1

По сохранённому ledger и подтверждению Artist выполнены **2 первичные операции встроенного image_gen: M1=1, M2=1; retries=0; J2=0**. Внутренний model ID генератора не раскрыт; это не model ID сотрудников. Независимый QA проверил raw copies/provenance, но не наблюдал сами вызовы и не доказывает отсутствие незаписанных операций.

Оба raw — RGBA 1254×1254. Одинаковая нормализация всего квадрата до 512×512 через LANCZOS (коэффициент `0.4082934609250399`), затем fixed crops к native 195×350 и 221×454. Per-part fit, перенос/масштабирование осей и rig compensation отсутствуют. Prompt, ordered refs, actual tool args, raw, normalized, маски/layout, crops/transforms и metrics находятся в `process/M1/` и `process/M2/`.

| Маршрут | Что получилось | Outside-mask RGBA diff полного normalized atlas |
|---|---|---:|
| M1 — один mini-atlas | Полые тёмные окончания вместо непрерывной ткани, drift швов/силуэта/деталей, обрезание бедра fixed crop. Target J1 не достигнут. | 73 608 changed pixels |
| M2 — visible-first repair и композиция | Ближе к target, исходные защищённые пиксели сохранены; внутри ремонта утрачены запас и часть покрытия. | raw 71 437 → final **0** |

Инструмент не имел отдельного mask API: бинарная маска передана как reference. Затем compositor использовал normalized raw внутри маски и **original RGBA вне маски**, включая RGB прозрачных пикселей. Нулевой final diff обеспечен этой обработкой, не точностью image_gen. TQ независимо реконструировал normalization/crops/composition, VQ отдельно проверил native final diff 0/0.

Внутри масок M2 потерял 1688 исходных alpha≥128 пикселей бедра и 260 голени; нижний alpha-bbox бедра сократился на 17 native px. Это потеря запаса текстуры, не изменение длины кости и не автоматическое доказательство сквозной дыры. Вывод M2 предпочтительнее M1 относится к этому фрагменту и полным процессам с разной обработкой; средняя цена, повторяемость и универсальное превосходство не измерены.

J2 получен без генерации из master crop `[139,920,278,1090]`: агентская polygon selection, alpha mask, uniform .48 и placement `[68,0]` на canvas голени. Точный процесс в `process/J2/`; это ручной выбор агента над существующими художественными пикселями, не автоматическая сегментация и не рисование персонажа примитивами. Его неудачный вид сохранён без подмены мотива.

- Lead в closeout выполнил только чтение reviews/responses, hash/contract/candidate verification и `npm test` **6/6**; нового browser/build/art-прохода не было. 76 frozen файлов сохранены. Записи — `coordination/lead-verification/`; скрипт `coordination/verify-closeout.py`.

Desktop border уменьшает canvas с 440 до 438 CSS px, поэтому .42/.84 — renderer transforms, эффективные desktop ≈.41809/.83618. Mobile пропорционально уменьшает холст и складывает панели вертикально; несколько вариантов не помещаются одновременно в экран. Это раскрыто, actual canonical transforms общие. Ошибки экспорта отдельных telemetry arrays и framing mobile screenshots раскрыты в reviews; потерянные времена не восстановлены выдуманными числами. Позиционная непрерывность smoothstep не гарантирует непрерывной скорости, человеческой естественности или 60fps. Полная походка, опора, физика, все углы/моменты запросов и реальные телефоны не исследовались.

## Остановка, доставка и дальнейшее применение

CTO остановил Q6 после полного candidate → reviews → responses. Repair J1 без потери запаса или новый широкий наколенник потребовали бы новой гипотезы/материала/контракта. Существенного implementation blocker нет, косметическая доводка не оправдывает correction. Неполучившееся качество остаётся неполучившимся после приёмки.

Полезно переносить: сначала сверять declared joints с реальными runtime offsets/layers; сравнивать арт на общем pose/clock; для точной защиты пикселей применять явную композицию и отдельно оценивать содержимое маски. Нельзя переносить как рецепт: «маска соблюдается генератором», «открытая линия всегда лучше», «наколенник всегда решает стык» или «atlas хуже ремонта».

Итог очереди — [сравнительный вывод Q1–Q6](../../docs/Q1_Q6_COMPARATIVE_CONCLUSION.md). Q1–Q5 и исходный 5.6 не меняются, чужие dirty/untracked не включаются. Доставка — один narrow commit; release отдельно после проверки CTO. Сервер PID63020 оставлен, новые кадры/генерации/коррекции не запускаются.
