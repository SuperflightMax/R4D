# Независимая техническая проверка q2-c1

23 октября 2026. Technical QA `technical-qa-r4d-q2-gpt61-01`, thread `01a168d2-1468-73a3-bb5e-22ffa7ee87ba`. Назначение — Lead Q2. Только `experiments/q2-simple-character`, без исправления продукта.

**Итог:** проверенные функциональные сценарии прошли. Обнаружено небольшое ограничение контакта при ходьбе (TQ-01 ниже). Технического блокера показа в проверенном объёме не найдено. Это не художественный PASS и не решение о завершении PoC; решение остаётся за Lead/CTO после остальных просмотров.

## Версия и способ проверки

Незакоммиченный q2-c1 поверх `253ec9013f736468f9e7fad6d6bafa6f82ea2529`, версия из `CANDIDATE.md`. Все **20/20 SHA-256** из `output/playwright/builder/q2-c1-files.json` совпали до и после проверки: [до](hashes-before.json), [после](hashes-after.json). Код, manifest и PNG не менялись.

Настоящий dev URL `http://127.0.0.1:4182/`, отдельная headless-сессия Chromium Playwright CLI `q2-technical`, окно 1280×900. Встроенный IAB недоступен. Личный Chrome и мышь Макса не использовались. Manifest и 12 PNG вернули HTTP 200; в консоли 0 ошибок и 0 предупреждений.

Непосредственно нажимал кнопки через Playwright и осматривал сохранённые кадры реального canvas: idle, low, ходьбу, подготовку прыжка, полёт и возврат на землю, промежуточную позу и её продолжение. Оба маршрута шли по настоящему времени браузера, без подмены анимации. Дополнительные точные измерения — на паузе через существующий `__R4D.step(1/120)` с настоящим render; команды при этом также подавались нажатием кнопок. Mock/stub не использовались. Непрерывное видео глазами не оценивалось; визуальные выводы ограничены просмотренными кадрами, численные — указанной дискретизацией и наблюдателем продукта.

## Пакет замечаний и ограничения

**TQ-01 — небольшой зазор обеих подошв при ходьбе, низкая значимость для PoC.** На части цикла герой слегка висит над поверхностью. В измеренном полном цикле минимум из зазоров двух стоп меняется от 0,001 до **1,394 экранного px**. Это не провал locomotion, но нельзя утверждать непрерывный точный контакт на всём шаге.

Воспроизведение: 1280×900, пауза → «Сначала» → «Идти» → продвинуть существующим `__R4D.step` до t=2,325 с. Фаза 0,66618; зазоры Near=1,780, Far=1,394 экранного px. [Кадр](walk-gap.png), численные данные и сценарий — `contact-result.json` / `contact-check.js`. Измерение использует alpha ≥128 и преобразования настоящих PNG; субпиксельная фильтрация/сглаживание скриншота не тождественны этой границе. Не требую автоматически доработки: соразмерность исправления решает Lead.

В просмотренных low и полёте также видны выступающие округлые части таза/бедра и сильное перекрытие варежек; они согласуются с известными ограничениями кандидата. Их художественную приемлемость этот технический отчёт не устанавливает. Естественность движения и чистоту стыков не вывожу из счётчиков и координат.

Не проверены production dist, другие браузеры/размеры окна, клавиатурное управление, все возможные моменты запросов и длительная работа. Случайный перебор и полный регресс не проводились. Изолированный браузер закрыт; общий сервер оставлен работающим. Созданы только материалы внутри `qa/technical/`; commit/push не выполнялись, чужие журналы и корневая `.playwright-cli/` не затронуты.
