## Воспроизводимое геометрическое правило

Для каждого из 16 принятых четырёхугольников опор Water используется середина
ближнего/переднего ребра (последовательные принятые вершины 2→3) в нативных
координатах вместо среднего положения всех 4 вершин. Скрипт проверяет, что
середина ребра 2→3 имеет наибольший native-Y; порядок вершин и сам многоугольник
не исправляются. Используется исходное смещение P1. Левая и правая части
сохраняют поле depthNativeY, перемычка — поле depthLineNative, соединяющее
середины двух передних рёбер. Правило не зависит от seed, тика, траектории
или радиуса шара.

Обычный нативный запуск seed1 воспроизведён без записи в существующий
закреплённый скомпилированный модуль
(`af8e6dea9ee5c46759f99ba3b68f4afa91c740b4fd2aba2d2d3f65bfa66753fa`).
Байты config с хэшем 9048b28a совпали с P1; состояние 1014 точно совпало
с checkpoint Builder. Исход остался LOST на 1196. Выигрышный seed не подбирался.

В EVALUATION.json оценено пересечение alpha шара по фактическим состояниям
1006–1035 и закреплённым projection/r16/lift0.65 с билинейной выборкой Pillow:
старый порог переключается на 1015 при геометрическом пересечении alpha 21.324%;
новый — на 1021 при остаточном пересечении 0.001%. Это обосновывает проверку
коррекции данных. Фильтрация отличается от Pixi, перекрытие тени этой оценкой
не проверялось. Это не независимая QA, не просмотр фактического движения
и не художественный PASS.

Сравнительная проверка Builder: тот же seed1, кадры 1006–1018 с продолжением
через 1020/1021/1022 для просмотра нового переключения. Проверить шар и
отдельную тень в обычном масштабе и при увеличении; сохранить плохие результаты.
Для остальных арок/seed ещё нужны обычные фактические проверки Pixi.
Универсальность коррекции не заявляется.
