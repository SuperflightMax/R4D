# Q3C — первый живой срез

Внутренний construction candidate `q3c-slice-01`: маячок → падение → контакт → выход четырёх связанных лап → выход глаза → живой idle и наведение взгляда. Чистового арта, ходьбы, большого превращения и охоты в этом срезе ещё нет. Anchor не используется как цельный спрайт. Исходники старых опытов не копировались.

Из `D:\dev\R4D\experiments\q3c-victorian-mantis`:

```powershell
npm ci
npm test
npm run build
npm run dev
```

Страница: `http://127.0.0.1:4187/`. Первый pointerdown (включая touch) по сцене или keydown запускает посылку. Курсор/касание задаёт цель взгляда. «Заново» возвращает ожидание. В обычном запуске seed берётся из `crypto.getRandomValues`; `?seed=42` закрепляет начальные фазы idle. Обычная сцена развивается в реальном времени.

Для пошаговой QA: `http://127.0.0.1:4187/?seed=42&paused=1`. После загрузки доступен `window.__Q3C__`:

```js
const q = window.__Q3C__;
q.activate();           // либо настоящий click/tap/key, пока часы на паузе
q.step(1 / 120);        // приращение времени, секунды
q.snapshot();          // phase, tick, seed, events, pointer, gaze, pose
q.seek(3.225);          // сброс + активация + повтор от начала до времени
q.setPointer(160, -180);
q.step(1);              // воспроизводимое наведение глаза
q.resume();            // обычный темп
q.pause();
q.reset(42);           // новое ожидание с seed, текущая пауза сохраняется
```

`seek` повторяет начальное состояние без истории пользовательского ввода. Для повтора заданного ввода используйте одинаковые `reset(seed)`, `activate`, `setPointer`, `step` в том же порядке. Симуляция идёт с фиксированным шагом 1/120 с; отрисовка не меняет состояние.

Границы после активации: 0–0.4 `beacon`; 0.4–1.45 `falling`; 1.45–2.35 `impact`; 2.35–4.5 `legs`; 4.5–5.75 `eye`; от 5.75 `capsule`. `pose.legs[*].world` содержит hip/knee/foot, `upper/lower` — постоянные длины. `pose.hatches`, `pose.lid`, `pose.eye` показывают реальные промежуточные положения. Мировой маячок и плоскость контакта — `(0, 0)`, вверх — отрицательный y. Все элементы рига существуют постоянно; непрозрачная броня и отдельные двери закрывают упакованные части.

Перед интеграцией финальных материалов ещё нужны согласование размерной схемы с художниками, проверка полного объёмного пути укладки/выхода и независимый живой просмотр. Unit/state PASS и эта конструкционная графика не являются художественной приёмкой Q3C.

Самопроверка Builder: unit/state tests, desktop 1280×720 и touch viewport 360×732. Свои кадры/CLI-снимки находятся в `tests/output/playwright/` и `tests/.playwright-cli/`; они не входят в product commit. `node_modules/` и `dist/` также не включать.
