# Q3C C2 · раскрытие механизма

Первый ввод по сцене или клавиатуре запускает маячок и посылку. После выхода лап и глаза «Раскрыться» или клавиша E запускает K0–K5. «Заново» возвращает ожидание. При фокусе на кнопке Enter и Space выполняют её штатное действие. Курсор и касание задают направление взгляда.

Сборка из каталога Q3C проверена на Node 24.15.0 и npm 11.12.1. Зависимости закреплены в `package-lock.json`. Для чистого прогона используйте `npm ci`.

```powershell
npm test
npm run build
npm run preview -- --port 4188
```

Обычный прогон доступен на `http://127.0.0.1:4188/`. Для фиксированного seed и ручных часов используйте `http://127.0.0.1:4188/?seed=42&paused=1`. Без параметра seed выбирается при загрузке страницы.

```js
const q = window.__Q3C__;
q.assets;                      // ID production pack, число узлов и загруженных текстур
q.reset(42);
q.activate();
q.step(7);
q.transform();                 // реальная команда перехода, когда капсула жива
q.step(1.70);
q.snapshot();                  // K2 и геометрия того же графа
q.trace();                     // тот же тик, включая реальные узлы Pixi
q.seek(9.49, { transformAt: 7 }); // повтор от начала, команда на 7-й секунде
q.setPointer(160, -180);
q.step(1);
q.resume();
q.pause();
```

`seek` повторяет начальную сцену с текущим seed и заданным временем команды. Для повтора истории ввода выполните те же `reset`, `activate`, `setPointer`, `transform` и `step` в том же порядке. Симуляция идёт с частотой 120 Гц. Позиция упакованной капсулы рассчитывается в ожидании и фиксируется при активации.

`snapshot().pose.parts` содержит постоянные ID и родителей, локальные крепления и мировые XY до экранной проекции. Углы в радианах, ось y направлена вниз. `local.roll` задаёт поворот плоскости створки вокруг шарнира. Ключ `pose.beat` показывает K0–K5 по фактическому времени от команды. При просмотре через `seek` целевой момент округляется вниз до шага симуляции.

У ноги `world.ankle` — конец жёсткого звена, `world.foot` — текущий контакт пятки или носка, `anchor` — его опорная точка. За движением приводов следят `pinDistance` гильзы и локальные позиции вложенных секций. Глаз всегда доступен по `eye.lens`. Координаты деталей используют pivot и trim манифеста `assets/rig/FULL_RIG_V1.json`, а времена — его `motion.keys` и отдельные дорожки.

## Привязка к TQA

В копии коллектора оставьте `snapshot()` для ожидания фазы. Для `preAction` и записи `frames` используйте `trace()` после штатного действия или `step(1 / hz)`. `trace()` копирует последний переданный рендеру тик и читает фактические матрицы и ID объектов. Время при чтении не меняется.

| Поле | Данные |
| --- | --- |
| `q.timing` | `hz = 120`, капсула доступна через 5,75 с после активации, переход длится 4,22 с. `beatOffsets` хранит смещения от действия в тиках. |
| `tick`, `phase`, `seed`, `events` | Фазы коллектора `capsule` и `mantis`, между ними `transforming`. Кнопка `Раскрыться`, поверхность `#stage`. Команда `transform` фиксируется на том же тике, что и предыдущее состояние. |
| `keyTicks` | Абсолютные native ticks K0–K5 после команды. K0 совпадает с тиком `preAction`. |
| `render.parts[id]` | `token` — UID реального контейнера Pixi, `parent` — физический родитель, `asset` — стабильный ID основной текстуры или `rig:<id>` для узла без поверхности. `surface` — выбранная лицевая или оборотная текстура. |
| `render.parts[id].matrix` | `[a,b,c,d,tx,ty]` из реального объекта Pixi с исключённой камерой. Учитывает проекцию глубины и поворот плоскости створки, поэтому створка сжимается у ребра. `render.camera` даёт масштаб и смещение в CSS-пикселях. |
| `render.parts[id].physicalMatrix` | Матрица той же детали в физических XY до проекции. Используйте её для осей, длин, постоянного физического масштаба и контакта с полом. Сверяйте экранные просветы по `matrix`. |
| `planted`, `pose.legs` | Четыре ID стоп из `stageDInterfaces.walk` и фактические точки переката. Физический пол `y=0`, `U=180`. |
| `pose.motion`, `pose.idle`, `pose.parts[id].local` | Все 28 дорожек до добавки покоя, фактически взвешенные добавки покоя и локальная геометрия после решения IK, привязки приводов и взгляда. Для анализа перехода берите базовую дорожку по ID и сверяйте её с локальной геометрией. Единицы `motion` и `idle` соответствуют манифесту. Угловые дорожки переводятся из градусов в радианы. Для регулятора используйте `shell.regulator.local.rotation`. |
| `pose.hatches`, `pose.lid`, `pose.shoulderInBody` | Текущие углы нижних и передней створок и положение плеча в раме. Остальные углы доступны в `pose.parts[id].local.roll`. Пределы окон заданы в `FULL_RIG_V1.json` → `apertures`. |

Для браузерного прогона из `tests/` откройте локальный preview через Playwright CLI и выполните сценарий.

```powershell
npx --yes --package @playwright/cli playwright-cli -s=q3c-c2 open http://127.0.0.1:4188/ --browser chrome
npx --yes --package @playwright/cli playwright-cli -s=q3c-c2 run-code --filename=c2-smoke.js
npx --yes --package @playwright/cli playwright-cli -s=q3c-c2 close
```

Сценарий проходит обычный темп на 1440×1000, 390×844 и 360×732, проверяет кнопку, постоянство ID, опоры, оба idle и перезапуск. Кадры выхода лап и K0–K5, а также `c2-render-trace.json` со снимком до команды и на ключевых тиках остаются в игнорируемом `tests/output/playwright/`. Для независимого прогона TQA связывает свою полную трассу с SHA кандидата, SHA-256 сборки и viewport.

Самопроверка покрывает движение текущего рига и посадки приводов. Для независимой приёмки нужны живой просмотр перекрытий, читаемость обоих серпов и оптики на телефоне и сверка зазоров по фактическим контурам. Ходьба и охота относятся к Stage D.
