# R4D — первый проход GPT-5.6 Sol

Браузерный proof of concept скелетной 2D-анимации одного растрового персонажа.
Демо собирает персонажа только из отдельных художественных PNG в `assets/`,
привязанных к иерархическому ригу через `assets/manifest.json`.

## Чистый запуск

Требуется Node.js 24+.

```powershell
npm install
npm run check
npm run dev
```

Vite напечатает локальный адрес демо. Для проверки production-сборки:

```powershell
npm run build
npm run preview
```

`npm run check` последовательно проверяет настоящие PNG и manifest, прогоняет
тесты логики состояний и собирает production-версию в `dist/`.
При production-сборке исходник, manifest и отдельные PNG копируются в
`dist/assets/`; демо не зависит от файлов за пределами `dist/`.

## Управление

- `A` / `D` или `←` / `→` — движение влево и вправо; отпускание запускает
  переход к стойке.
- `Space` — прыжок из стойки или движения.
- `P` — пауза времени в любой фазе.
- `B` — показать или скрыть кости, суставы и направления костей.
- `T` — автоматическая демонстрация стартов, остановок и прыжков.
- `R` — сброс в исходную стойку.

Панель слева показывает текущее/целевое состояние, фазу, намерение после
приземления и ход смешивания.

## Как устроен PoC

`assets/manifest.json` — единый контракт между художественной нарезкой и кодом.
В нём заданы:

- `parts`, где для каждой отдельной PNG указаны кость и её родитель, pivot в
  пикселях исходной части и глобальный слой;
- путь к сохранённому цельному исходнику и масштаб показа.

Локальные координаты и смысловые роли единственного рига зафиксированы рядом с
его реализацией в `src/rig.ts`; они отделяют художественные имена от анимации.
Риг вычисляет мировую
трансформацию по иерархии, но держит все спрайты в одном сортируемом слое — так
ближние и дальние конечности сохраняют явный глобальный порядок.

Все состояния выдают позу одного формата. При любой смене состояния контроллер
запоминает реально показанную сейчас позу и одним механизмом непрерывно
смешивает её с новой целью. Таблицы переходов между парами состояний нет.
Запрос движения хранится отдельно от фазы прыжка, поэтому после приземления
персонаж возвращается в актуально запрошенную стойку или движение.

Наземный цикл разделяет опорную и переносную фазу: опорный ботинок остаётся у
линии земли, а свободная нога сгибается в новом коленном суставе. Скорость тела
набирается и гасится плавно отдельно от смены позы. Обычные старт/остановка
смешиваются за 0,38 секунды; через первые 55 мс переход выполнен примерно на
13%, поэтому изменение читается как движение, а не как скачок.

Прыжок состоит из четырёх наблюдаемых участков: сжатие с ботинками на земле,
разгибание и отрыв, дуга с подобранными ногами, затем посадочная амортизация.
Положение рук, головы и ног ограничено диапазонами из manifest.

## Основные файлы

- `src/animation.ts` — позы, общий механизм смешивания и машина состояний;
- `src/rig.ts` — загрузка manifest, иерархический риг, слои и диагностика костей;
- `src/main.ts` — PixiJS-сцена, ввод и диагностическая панель;
- `src/animation.test.ts` — проверки непрерывности перехода и прыжка;
- `scripts/validate-assets.mjs` — проверка структуры manifest и реальной альфы PNG.

Это намеренно узкая реализация одного персонажа: не редактор, не autorig и не
универсальный движок анимации.

Активный manifest v2 использует 14 отдельных PNG. Каждая нога разделена на
бедро и голень с ботинком; корпус сумки рисуется за torso, ремень — перед ним,
а отдельный `collar_cover` закрывает шейный запас. Старые цельные ноги и сумка
сохранены только как история кандидата 1 и демо их не загружает.

Реальный видимый ботинок входит в спрайт голени, поэтому отдельной вращаемой
стопы нет. В опорной фазе голень компенсирует угол бедра и держит ботинок
ровным; в переносе и полёте ботинок закономерно следует за голенью.
