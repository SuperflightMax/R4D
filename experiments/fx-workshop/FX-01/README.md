# FX Workshop · FX-01

Одноразовый статический UX-прототип: два входа в одну сцену, черновик и композицию. Без сборки и внешних зависимостей. Канон — [FX-01-UX, редакция 1](../../../orders/fx-workshop/FX-01-UX.md) на `5c3a34b6d66ffca219ff825393dc7492cac9c84e`; план CTO ему подчинён.

## Открыть

Из `D:\dev\.codex-worktrees\r4d-fx01`:

```powershell
python -m http.server 18731 --bind 127.0.0.1 --directory experiments/fx-workshop/FX-01
```

Открыть `http://127.0.0.1:18731/` в разрешённом браузере. Остановить сервер — Ctrl+C в его терминале. Не открывать HTML через `file://`: для постоянного локального хранилища нужен стабильный HTTP-origin. Смена порта, адреса, браузера или профиля открывает другое хранилище.

«От эффекта» показывает виды эффектов и живые варианты; «От объекта» начинает со списка объектов. Оба входа используют одни эффекты и состояние. Объект также выбирается на сцене или в поле «Цель». Наведение на вариант временно примеряет его; уход или Esc возвращает черновик. «Применить» добавляет эффект, «Заменить шаг» меняет выбранный, «Добавить шаг» сохраняет существующий и добавляет следующий.

Колесо над числом меняет его без фокуса; Shift даёт точный шаг. Круглая ручка справа от центра траектории меняет радиус, поддерживает drag и клавиши влево/вправо. Параметры сразу показывают выбранный шаг; «Повторить» запускает композицию от начала. «Одновременно» и «После» относятся к предыдущему шагу списка, задержка добавляется к этому началу. Первый шаг всегда начинается от начала композиции. Ненужный шаг можно убрать и вернуть через Undo.

Черновик сохраняется локально автоматически после жеста или паузы. «Закрепить» создаёт рецепт с автоименем и превью; имя меняется прямо в коллекции. «Открыть в черновике» позволяет пробовать изменения без перезаписи сохранённой работы. «Сохранить редакцию» обновляет ту же карточку, сохраняя предыдущую редакцию. Её можно вернуть в черновик из коллекции и при желании явно сохранить как новую редакцию. Undo/Redo относятся к текущей сессии (до 80 шагов); сохранённые редакции переживают перезапуск браузера. Ctrl+Z/Shift+Ctrl+Z/Ctrl+Y работают вне полей; в полях остаётся обычная отмена ввода.

## Проверка и границы

Для технических проб открыть, например, `http://127.0.0.1:18731/?test=my-check`. Такое имя создаёт отдельное тестовое пространство, не очищая пользовательское. В обычном интерфейсе технической панели/reset нет. Не использовать реальные рецепты участников для тестирования.

[Самопроверка M01–M11](SELF-CHECK.md) содержит результаты, сценарии повторения и сохранённые скриншоты. `checks/interaction.js` и `checks/extra.js` — функции для `playwright-cli run-code --filename=...`, не тесты фреймворка и не код приложения. Они используют уже запущенный изолированный браузер и порт 18731; никаких установок не выполняют. Прогон `interaction.js` создаёт собственный новый `?test=builder-...`, возвращает URL и результаты. Для `extra.js` сначала закрыть браузер CLI и снова открыть возвращённый URL **с тем же отдельным persistent profile**. Выводы/профиль проверочного браузера направлять в `D:\dev\.codex-task-temp\r4d-fx01\builder\`; личный Chrome и рабочий стол не занимать. Сам скрипт сохраняет снимки в `...\builder\output\`.

Это кандидат для внутренней проверки, без деплоя. Физический fullscreen 1920×1080 (M11), независимая QA и наблюдения Макса/Славы ещё не выполнены. Headless-проверка не является человеческой приёмкой. Production-runtime, серверное сохранение, игровой экспорт, мобильный редактор и FX-02+ здесь не реализуются. Варианты фиксированы, случайного генератора/seed нет. Данные остаются в браузере; запрет/переполнение хранилища явно показываются как «Не сохранено».
