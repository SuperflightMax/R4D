## Основание разрешённого старта

Макс прямо разрешил архитектору написать и закоммитить начальные задачи без предварительного ревью всего плана: «таск по нстартовым штуками МОЖНО БЕЗ МОЕГО РЕВЬЮ ПЛАНА». По последующему поручению через ДотМакса исполнение передаётся **новой команде через действующего CTO**, а не старой очереди.

Разрешён только ART-00, затем два независимых потока ART-01 и ART-02 в границах START. Продуктовые остановки G1/G2 обязательны. Старые остановленные очереди, включая Q3C, не возобновлять. Нового API-бюджета и расходов нет. Product Lead остаётся внешним чат-собеседником; кадровую роль ему не добавлять.

## Действие Дота и CTO

1. Дот доставляет точный remote commit с этой редакцией **существующему CTO R4D**. Не создавать замену CTO по одному факту обнаружения файла. При неопределённом исходе доставки сначала проверить получение, не дублировать запуск.
2. CTO подтверждает прочтение канонического START и его границ; организует новую изолированную работу, состав и короткую оценку по действующим правилам. Дополнительного согласования всей программы для этого старта не нужно.
3. Фактические получение, начало, блокеры, материалы и ожидание G1/G2 отмечаются отдельно в `experiments/art-2d/START_STATE.md`. Пока такой факт не подтверждён, наличие этого файла/commit означает только публикацию заказа.
4. Выдать Максу/Славе два компактных зрительных пакета, реальные длительности и точный следующий вопрос. Без продолжения следующих волн по молчанию и без переключения на платный API.

Автор этой выдачи публикует план/заказ. Публикация сама по себе **не подтверждает** старт команды, выполненную генерацию, доступность среды или одобрение человеком результатов.
