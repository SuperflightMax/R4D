## Результат

Один дешёвый живой прототип для сравнения входов A (от эффекта) и B (от объекта). Общие эффекты, сцена, имена, параметры и состояние. Переключение не теряет выбранный объект, черновик и композицию. Цепочка: найти → временно примерить → применить → изменить → сочетать → отменить → закрепить → закрыть и вернуться. Конечный результат этапа — наблюдения и продуктовое решение Product + Max, не просто работающие кнопки и не обещание художественной ценности.

Общие заметно разные живые варианты и простая последовательная/параллельная композиция. Этот набор проверяет действия, красота и количество FX не являются целью.

Первая наблюдаемая точка после 4–6 активных часов: оба входа в одну сцену, ясная цель, временная примерка, применение и видимое изменение параметра, переход A↔B без потери работы. Оставшееся обозначить явно; промежуточный срез не выдавать за полный candidate. Затем самостоятельно довести **всю карточку**, включая сохранение, редакции, групповое Undo и прерывание воспроизведения, а не ждать новых микропоручений.

Три состояния честные: preview не трогает черновик/историю/коллекцию; применение меняет отменяемый черновик; закрепление создаёт рецепт с автоименем и узнаваемым превью. Изменение открытого рецепта не портит сохранённую редакцию до явного сохранения. Сохранение обновляет ту же карточку с предыдущей редакцией. После закрытия/открытия в том же браузере работа восстанавливается. Undo текущей сессии и история редакций различаются. Если используется случайность, фиксировать seed; можно использовать фиксированные варианты.

Для технических прогонов предусмотреть отдельное тестовое пространство состояния, не смешивающееся с настоящими рецептами. Оно не должно появляться как техническая панель в обычном пользовательском потоке. Отсутствие/ошибку local storage не выдавать за успешное сохранение. Не уничтожать настоящую коллекцию ради reset.

Сдача Builder: исходники, короткий README с точным запуском и границами, самопроверка по матрице, candidate commit и список реально оставшихся проблем. Коммиты включают только свою область. Push согласовывать с CTO по очереди записи Git; никаких параллельных commit/index-операций с CTO.

## Показ и решение

После внутренней проверки — точная опубликованная версия на существующей разрешённой площадке R4D/Superflight Space. Сохранить связь URL ↔ commit и проверить доставленные байты/основной сценарий. Публикация сама по себе не приёмка. Новые права, доступы, установки, платные API/хосты или расходы не разрешены; зависимый шаг остановить и сообщить конкретную потребность.

Макс и Слава выполняют одинаковые пять задач из §6 карточки. Один начинает с A, другой с B; для первого знакомства одинаковые начальные условия, для переключения — изменённый черновик. Фиксировать затруднения, подсказки, прокрутки, ошибки колеса, потерю контекста, порядок и эффект обучения. Ориентир 20–40 минут на человека, доступность отдельно. Не строить статистический рейтинг по двум людям.

Итог: краткое сравнение, рекомендация начального пути и обнаружения второго, правил композиции/состояний/сохранения, фактические затраты и оставшиеся неизвестные. После решения Product + Max остановиться. FX-02+ не открывается автоматически.
