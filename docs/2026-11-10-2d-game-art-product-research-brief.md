# R4D — создание арт-сетов для 2D-игр: продуктовый замысел и план исследования

**10 ноября 2026.** Обсуждение Макса и Product Lead ArtFoldi (Арфолди). Материал для архитектора R4D.

**Статус:** продуктовый бриф: наблюдения Макса, желаемая ценность и предлагаемая структура исследования. Не техническое задание CTO, не утверждённый набор опытов, не решение о найме/расходах. Архитектор с Максом уточняет границы и формулирует заказ; CTO предлагает средства, команду и план.

## Зачем и кому

У проекта нет штатных художников. Уже умеем получать впечатляющие концепт-картинки, но превращение их в настоящий уровень или сцену часто теряет выразительность: геометрия, нарезка, объекты, перекрытия, тени, анимации, эффекты и интеграция выглядят значительно слабее исходного образа. Текущие способы Level Workshop / OpenClaw / VPS — лишь варианты, а не ценность, которую обязательно надо сохранять.

**Главная ценность:** Слава, Макс или другой автор способен придумать сцену, мир, настроение или представить референс, а команда ИИ-агентов — создать из этого художественно сильный, согласованный, управляемый **арт-сет для реальной 2D-игры**, без обязательного труда художника. Система должна как воплощать человеческий художественный замысел, так и самостоятельно предлагать неожиданные хорошие решения. Эти способности дополняют друг друга.

Польза исследования не зависит от немедленного выпуска очередной доски Millionko. Но практический приоритет сейчас — **красивое игровое оформление**, а не необычайно сложная механика. Технологический опыт должен переноситься и на другие 2D-игры.

## Что именно хотим выяснить

1. **Потолок художественного качества.** Какие виды визуальных миров, стилей, материалов, композиции, перспективы и атмосферы способны создать агенты? Когда получается художественно впечатляющий результат, когда — примитивная или шаблонная графика? Сравнивать итоговый вид, а не убедительность отчёта.
2. **От концепта до игрового арт-сета.** Можно ли получить полноценные слои, фоны, отдельные объекты, маски, перекрытия, тени и состояния, сохранив красоту цельной картинки? Сравнить принципиально разные пути: цельный концепт → разборка; объекты → сборка сцены; геометрия/конструкция → художественная отделка; подходящие гибриды. Не считать статичный красивый коллаж готовым игровым сетом.
3. **Движение и эффекты.** Какой уровень анимаций объектов/персонажей, состояний, переходов, частиц, реакций и света реально получается в едином художественном стиле? Как выглядит итоговая сцена в движении, а не отдельные исходники? UI/HUD и лобби тоже входят в область возможностей оформления 2D-игр, хотя не обязаны входить в каждый опыт.
4. **Управляемость и художественная цельность.** Можно ли целенаправленно изменить одну вещь, не разрушив другую; досоздать объекты и новые состояния в том же стиле; исправить брак; сохранить образ при подготовке ассетов? Способен ли агент предложить удачное художественное решение сам, а не просто следовать подробному референсу?
5. **Повторяемость, сложность, время и цена.** Как часто получается хороший результат, сколько требуется попыток и вмешательств, что действительно повторяется у свежей команды? Где предел сложности сцены и количества объектов? Сколько обходится удачный пригодный арт-сет, а не одна генерация? Отдельно считать удачные и неудачные проходы.

Важное различие: повторяемость художественного процесса — это воспроизводимая способность достигать сопоставимого качества, а не обязательное совпадение пикселей при каждом вызове модели.

## Предлагаемый ход исследования — продуктовые линии, не маршрут исполнителей

**A. Разведка доступных способов.** Выяснить реальные доступные возможности и ограничения: генерация/редактирование в ChatGPT Pro, работа через Codex по подписке, через OpenAI Images API и Responses API, другие доступные инструменты/модели по смыслу. Не требовать перечислить весь рынок. Важна проверяемая польза для арт-сетов, не технологический каталог.

**B. Художественный замысел.** Независимо проверить создание выразительных концептов по сильному референсу и по открытому брифу, где художник-агент сам предлагает решение. Не ограничивать все эксперименты терминологией Pachinko или конкретным игровым жанром.

**C. Производственная материализация.** На сопоставимых художественных целях проверить разные подходы к получению пригодных слоёв/объектов и итоговой сцены. Показывать **собранный игровой вид**, а не только красивые исходные генерации. Текущие опыты перспективы и нарезки R4D — полезная доказательная база, не повод заранее назначить один подход победителем.

**D. Анимация, эффекты, интерфейс и интеграция.** По необходимости исследовать недостающие классы игровых ассетов и увидеть реальные результаты в 2D/Web/PixiJS, включая движение и перекрытия. Не требовать разработки новой игровой механики ради проверки арта; использовать простые уже существующие взаимодействия или события.

**E. Повторы и художественные правки.** Повторить удачные способы с иным материалом/стилем/свежим исполнителем; проверить управляемость, типовые неудачи и затраты. Возможно несколько победителей для разных задач; универсальный единый конвейер не является целью.

Архитектор определяет разумные раздельные опыты и их очередность с учётом команды, занятости и стоимости. Начальные пробы должны быть достаточно дешёвыми, но не должны исключать самое качество, ради которого затеяли исследование.

## Специальный вопрос: Pro против API и бонуса $200

Макс уже использует ChatGPT Pro; ChatGPT/Codex по подписке умеют создавать и редактировать изображения. **Нет принятого предположения, что API автоматически рисует лучше.** В ноябре Максу предоставлен бонус **$200 на API-эксперименты приблизительно на месяц**; это возможность отдельного сравнительного опыта, но не повод расходовать бюджет ради самого расходования.

По актуальной документации OpenAI API доступны генерация и редактирование изображений, в том числе Images API для прямых запросов и Responses API для многошаговой работы. У API есть управляемые параметры и возможности автоматизации. Некоторые функции (например, прозрачность, работа с референсами, правки, GIF) уже доступны в существующих инструментах; **не объявлять их уникальным преимуществом API без сравнения**. [Официальное описание API](https://developers.openai.com/api/docs/guides/image-generation).

Исследуемая разница:
- отличается ли **качество готового изображения/ассета** при сопоставимых брифах и доступных моделях;
- отличается ли **точность правок, сохранение стиля, устойчивость результата**;
- даёт ли API выигрыш в **управляемости, массовых попытках, автоматизации сборки и учёте затрат**;
- компенсирует ли выигрыш API отдельную стоимость/сложность относительно уже оплаченной подписки.

Для честного сравнения сохранять одинаковый творческий бриф, доступные референсы и желаемый итог. Отдельно различать эффект **модели**, **интерфейса доступа** и **многошагового агентского процесса**. Отмечать фактические параметры, число попыток и стоимость; нельзя считать разные модели с разными подсказками чистым доказательством преимущества API. До платных опытов проверить, какие модели реально доступны в нужном проекте/API, срок и условия бонуса, предложить Max понятный предел расходов; в ходе работы не тратить всё автоматически.

## Как выглядит полезная выдача

- Визуально доступная подборка **реальных финальных арт-сетов/собранных сцен** с входными идеями, а не только отчётами и разрозненными картинками.
- Для каждого существенного подхода — что удалось, где теряется качество, что не проверено, насколько результат управляем и повторяем, сколько стоил.
- Несколько пригодных путей для разных типов оформления, если они действительно обнаружены; не требуется один универсальный метод.
- Понимание границ на сегодня и что стоит пробовать дальше. Даже отрицательный результат полезен, если проверена настоящая трудность, а не её упрощённая подмена.
